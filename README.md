# 社区新生儿上门访视 · 黄疸记录与复查随访系统

面向社区护理场景的全栈演示应用：产妇出院后，社区护士上门访视新生儿，记录黄疸、体重、喂养、脐带、大小便与产妇恢复情况；系统按**出生天数 + 黄疸值 + 体重变化 + 喂养次数 + 排便颜色 + 产妇恢复 + 家庭照护能力**综合评估风险，自动生成复查、转诊、母乳指导、电话随访等随访事项并跟踪闭环。家属端可查看护理建议、复查时间与风险说明，补充出生证明/出院小结/喂养记录，发起线上咨询与改约。护士上门现场网络不稳定时，访视先存**本地草稿**，回到社区后在同步中心**幂等补齐**。**护士按约到达但家属拒绝开门、只愿电话沟通时，登记到达时间/电话内容/拒访原因/是否看到婴儿；连续拒访自动升级社区医生或妇幼专员，由其决定上门复核（自动带入前次到达照片、电话记录与未完成测量项）或联系街道；拒访不会关闭访视任务，必须有明确后续安排。**

## 功能与角色

| 角色 | 功能 |
| --- | --- |
| **护士**（移动端优先） | 工作台（未访视家庭/异常黄疸/产妇风险/**拒访升级**/待闭环）、预约管理（改约、无人应答、**家属拒访登记**）、母婴档案（访视/测量/照片/建议/复查/转诊/材料/咨询/**拒访升级**/时间线同档管理）、访视记录表单（实时风险预评估、设备故障手工记录、拍照上传、**连续拒访后上门复核自动带入前次照片/电话/未完成项**）、**离线草稿与同步中心**、随访闭环处理、**升级工单中记录每次联系**、回复线上咨询 |
| **社区医生 / 妇幼专员** | 随访决策台：按档案聚合待处理事项，综合随访记录决定**复查 / 转诊 / 电话随访 / 母乳指导 / 继续观察**，决策自动转为新的随访事项并跟踪闭环；**连续拒访升级处置台：查看每次拒访与联系经过，决定上门复核（自动带入资料）/联系街道/同意恢复访视** |
| **家属** | 查看护理建议、复查时间、风险说明；上传出生证明/出院小结/喂养记录；发起线上咨询；申请改约 |

已覆盖的异常场景：家庭临时改约、家属不愿开门（未开门→再次预约事项）、**家属拒访只愿电话沟通（记录到达时间/电话内容/拒访原因/是否看到婴儿，首次拒访必须再约，连续 2 次自动升级，升级后每次联系留对象/语气/原因/见婴状态，医生上门复核自动带入前次资料）**、黄疸值接近阈值（按日龄阈值预警）、婴儿体重下降（>7%/>10% 分级）、产妇情绪异常、社区设备故障（手工记录标记+复测提醒）、家长线上咨询、离线草稿回社区后同步。

## 技术栈

- **前端**：React 18 + TypeScript + Vite，状态管理用 **Zustand**（Pinia 是 Vue 生态的状态库，无法用于 React；Zustand 提供与 Pinia 相同的 define-store 范式，含 localStorage 持久化）。移动优先响应式布局，适配护士上门现场操作。
- **后端**：Node.js + Express，SQLite（better-sqlite3）文件库，首次启动自动建表并写入演示数据。
- **风险引擎**：`server/risk.js` 与 `client/src/risk.ts` 同构——表单实时预评估与服务端落库结论一致。

## 一键启动（Docker）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

- 单容器交付：多阶段构建前端 → 后端托管静态页 + REST API + SQLite 初始化。
- 数据持久化在命名卷 `nbv-data`（删除容器不丢数据）；删除卷后重启可重置演示数据。
- 国内网络构建可指定镜像源：`NPM_REGISTRY=https://registry.npmmirror.com docker compose up --build`

## 本地开发

```bash
npm run install:all     # 安装 server 与 client 依赖
npm run dev:server      # 终端1：后端 http://localhost:8080（自动建库+种子数据）
npm run dev:client      # 终端2：前端 http://localhost:5173（/api 代理到 8080）
```

生产模式本地运行：`npm run build && npm start`，然后访问 http://localhost:8080 。

## 风险判定规则（`server/risk.js`）

- 经皮胆红素按出生日龄分档阈值（µmol/L）：≤1 天 137 / 2 天 205 / 3 天 257 / ≥4 天 291；**达阈值→危急+转诊**，**距阈值 ≤34→接近阈值预警+24~48h 复查**。
- 体重较出生下降 **>10%→危急+转诊+母乳指导**，**>7%→高风险+母乳指导+复测**。
- 喂养 <8 次/日、白陶土色大便（危急转诊）、脐带渗血/化脓、嗜睡、产妇情绪低落/异常、伤口红肿渗液、家庭照护薄弱等均参与分级；设备故障手工记录强制复测提醒。
- 结论输出：风险等级（低/中/高/危急）+ 是否复查/转诊/母乳指导/电话随访 + 自动生成护理建议（家属端可见，护士可修改）。

## 家属拒访与连续拒访升级规则（`server/escalation.js`）

- 护士按约到达、家属拒绝开门只愿电话沟通时，登记：**到达时间、沟通对象/关系、对方语气、拒访原因、电话沟通内容、是否看到婴儿及婴儿状态、到达现场照片**。
- **拒访不关闭访视任务**：预约仅标记「家属拒访」；首次拒访必须与家属约定明确的再次上门时间（系统自动生成待访视预约 + 「再次预约」随访事项），缺少后续安排不允许提交。
- 自最近一次成功访视起**连续拒访 2 次**，系统自动**升级社区医生**（可指定妇幼专员），生成「拒访升级」随访事项；升级期间访视任务始终开放。
- 升级后**每次联系都留痕**：联系对象、与母婴关系、联系方式、语气、本次拒访原因、是否看到婴儿及状态、沟通内容。
- 社区医生/妇幼专员处置三选一，均有明确后续：**上门复核**（确定时间）、**联系街道/居委会**（记录对接人与协调事项）、**家属同意恢复访视**（约定时间）。
- 决定**上门复核**时，系统自动带入：前一次护士**到达照片**、历次**电话沟通记录**、按首次访视标准项计算的**未完成测量项**（体重/经皮胆红素/脐带/喂养/大小便/产妇伤口/产妇情绪），复核访视表单顶部展示，减少重复询问造成的家属抵触。
- 复核/恢复后真正完成一次上门访视，升级工单、待上门复核与「拒访升级/再次预约」事项才自动闭环。

## 主要 API

`POST /api/auth/login` · `GET /api/dashboard` · `GET/POST /api/appointments`（`/reschedule`、`/no-show`）· `GET /api/archives`（filter: unvisited/jaundice/maternal/refusal/unclosed）· `GET /api/archives/:id`（聚合 refusals/escalations）· `POST /api/visits`（`/assess` 预评估）· `POST /api/sync/visits`（离线幂等同步）· `GET /api/followups`（`/close`、`/decide`）· **`POST /api/refusals`（家属拒访登记）· `GET /api/escalations`（`/:id`、`/:id/contacts` 联系留痕、`/:id/resolve` 复核/街道/恢复）· `GET /api/rechecks/by-appointment/:appointmentId`（复核带入资料）** · `GET /api/family/overview` · `POST /api/documents` · `POST /api/consults`（`/reply`）
