# 社区新生儿上门访视 · 黄疸记录与复查随访系统

面向社区护理场景的全栈演示应用：产妇出院后，社区护士上门访视新生儿，记录黄疸、体重、喂养、脐带、大小便与产妇恢复情况；系统按**出生天数 + 黄疸值 + 体重变化 + 喂养次数 + 排便颜色 + 产妇恢复 + 家庭照护能力**综合评估风险，自动生成复查、转诊、母乳指导、电话随访等随访事项并跟踪闭环。家属端可查看护理建议、复查时间与风险说明，补充出生证明/出院小结/喂养记录，发起线上咨询与改约。护士上门现场网络不稳定时，访视先存**本地草稿**，回到社区后在同步中心**幂等补齐**。

**家属拒访处理（本次扩展）**：护士按预约到达但家属拒绝开门、只愿意电话沟通时，可登记结构化**拒访记录**（到达时间、到达照片、电话沟通对象与内容、拒访原因、家属语气、是否看到婴儿），拒访**不会关闭访视任务**，必须登记明确后续安排（再次预约 / 电话随访 / 等待家属联系）。同一家庭**连续拒访 2 次自动升级**给社区医生（升级单闭环后再次拒访则升级**妇幼专员**），由其决定**上门复核或联系街道**；升级流程中每次联系都记录对象、语气、拒访原因与婴儿可见性。决定上门复核后，复核访视页**自动带入前一次护士到达照片、全部电话沟通记录与未完成测量项**，减少重复询问造成的家属抵触；复核访视提交后升级流程自动闭环。

## 功能与角色

| 角色 | 功能 |
| --- | --- |
| **护士**（移动端优先） | 工作台（未访视家庭/异常黄疸/产妇风险/拒访升级/待闭环）、预约管理（改约、家属拒访登记、无人应答）、母婴档案（访视/测量/照片/建议/复查/转诊/材料/咨询/**拒访与升级**/时间线同档管理）、访视记录表单（实时风险预评估、设备故障手工记录、拍照上传、**上门复核信息包自动带入**）、**离线草稿与同步中心**（含拒访记录）、随访闭环处理、升级联系记录、回复线上咨询 |
| **社区医生** | 随访决策台：按档案聚合待处理事项，综合随访记录决定**复查 / 转诊 / 电话随访 / 母乳指导 / 继续观察**；在**连续拒访升级**中决定**上门复核 / 联系街道 / 转妇幼专员 / 电话随访 / 继续观察**，决策自动转为新的随访事项并跟踪闭环（上门复核须复核访视完成才能闭环） |
| **家属** | 查看护理建议、复查时间、风险说明；上传出生证明/出院小结/喂养记录；发起线上咨询；申请改约 |

已覆盖的异常场景：家庭临时改约、家属不愿开门（无人应答→再次预约事项）、**家属拒访隔门电话沟通（结构化拒访记录→连续拒访升级社区医生/妇幼专员→上门复核/联系街道→复核自动闭环）**、黄疸值接近阈值（按日龄阈值预警）、婴儿体重下降（>7%/>10% 分级）、产妇情绪异常、社区设备故障（手工记录标记+复测提醒）、家长线上咨询、离线草稿回社区后同步。

## 技术栈

- **前端**：React 18 + TypeScript + Vite，状态管理用 **Zustand**（Pinia 是 Vue 生态的状态库，无法用于 React；Zustand 提供与 Pinia 相同的 define-store 范式，含 localStorage 持久化）。移动优先响应式布局，适配护士上门现场操作。
- **后端**：Node.js + Express，SQLite（better-sqlite3）文件库，首次启动自动建表并写入演示数据。
- **风险引擎**：`server/risk.js` 与 `client/src/risk.ts` 同构——表单实时预评估与服务端落库结论一致。

## 一键启动（Docker）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

- 单容器交付：多阶段构建前端 → 后端托管静态页 + REST API + SQLite 初始化。
- 数据持久化在命名卷 `nbv-data`（删除容器不丢数据）；删除卷后重启可重置演示数据。
- 国内网络构建可指定镜像源：`NPM_REGISTRY=https://registry.npmmirror.com docker compose up --build`

## 本地开发

```bash
npm run install:all     # 安装 server 与 client 依赖
npm run dev:server      # 终端1：后端 http://localhost:8080（自动建库+种子数据）
npm run dev:client      # 终端2：前端 http://localhost:5173（/api 代理到 8080）
```

生产模式本地运行：`npm run build && npm start`，然后访问 http://localhost:8080 。

## 风险判定规则（`server/risk.js`）

- 经皮胆红素按出生日龄分档阈值（µmol/L）：≤1 天 137 / 2 天 205 / 3 天 257 / ≥4 天 291；**达阈值→危急+转诊**，**距阈值 ≤34→接近阈值预警+24~48h 复查**。
- 体重较出生下降 **>10%→危急+转诊+母乳指导**，**>7%→高风险+母乳指导+复测**。
- 喂养 <8 次/日、白陶土色大便（危急转诊）、脐带渗血/化脓、嗜睡、产妇情绪低落/异常、伤口红肿渗液、家庭照护薄弱等均参与分级；设备故障手工记录强制复测提醒。
- 结论输出：风险等级（低/中/高/危急）+ 是否复查/转诊/母乳指导/电话随访 + 自动生成护理建议（家属端可见，护士可修改）。

## 拒访与升级业务规则

1. **拒访 ≠ 无人应答**：预约状态新增「拒访」（家属在场、隔门电话沟通），与「未开门」（敲门无人应答）分列；拒访登记必须有电话沟通对象/内容，且必须选择明确后续安排（再次预约须填时间、电话随访须填再次联系时间），否则服务端 400 拦截。
2. **拒访不关闭访视任务**：每次拒访都生成开放的「再次预约 / 电话随访」事项与新的待访视预约（再次预约时），任务始终有待跟进状态。
3. **连续拒访升级**：同一家庭累计拒访 ≥2 次且无进行中升级单时自动建升级单——首次升级给**社区医生**；该升级单闭环后再发生连续拒访则升级至**妇幼专员**。
4. **升级处置**：社区医生/妇幼专员可决定上门复核（必须排复核时间，生成「复核」预约）、联系街道（必须写明协同事项）、电话随访/继续观察（必须填下次联系时间）、转妇幼专员；安排上门复核的升级单**只有复核访视提交完成后才能闭环**（其他处置需填写闭环依据）。
5. **复核信息包自动带入**：`review-brief` 聚合最近一次拒访的到达照片（若该次未拍照则回退到上一张）、全部拒访电话记录与升级联系记录、以及 12 项测量中此前未完成的项目；复核访视提交后自动把复核预约标记完成、闭环升级单与拒访遗留事项。
